# 硬件对齐: BQ27220 电量 SOC/FCC 稳定性

## 1. BQ27220 电量计

### 已有硬件

- 电量计芯片: BQ27220
- 软件 I2C:
  - GP25 = SCL
  - GP26 = SDA
  - GP27 = GPOUT
- BQ27220 直接由电池供电。
- BQ27220 最低工作电压约 2.4 V，低于产品电池截止电压 2.75 V。

### 对齐结论

- BQ27220 不会跟随 RP2350/ESP32 系统一起重启。
- 在电池电压高于 2.75 V 截止电压时，BQ27220 理论上仍处于可工作供电范围内。
- 因此低电反复重启后 FCC 回到 650，不应优先解释为 BQ27220 自身掉电重启。
- 更高优先级的解释是：RP2350 重启后当前固件再次执行 BQ27220 配置写入，把 FCC 覆盖回 650。

### 硬件需求

- IO 类型：通信接口，I2C。
- 电平：3.3 V 逻辑。
- 中断需求：暂不依赖 GPOUT 中断，先轮询。
- DMA 需求：不需要。

## 2. 低电保护相关硬件

### 已有硬件

- RP2350
- ESP32
- 高耗电 LED 链:
  - GP22 按键灯
  - GP40 环境灯
- GP24 = 5V boost enable

### 用户确认

- GP24 会影响 RP2350 和 ESP32。
- GP24 不影响 BQ27220，因为 BQ27220 是直接电池供电。

### 对齐结论

- 低电保护不能简单通过关闭 GP24 作为唯一策略，因为 GP24 会影响 RP2350 和 ESP32。
- 低电保护应优先从固件层面降低耗电：关闭 LED、降低亮度、停止高耗电效果、减少非必要外设活动。
- 如果未来要控制 GP24，需要明确它会不会导致系统整体掉电或 ESP32 复位。

## 3. RP2350 与 ESP32 电量信息链路

### 已有硬件

- UART:
  - GP44 = RP2350 TX -> ESP32 RX
  - GP45 = RP2350 RX <- ESP32 TX
- RP2350 从 BQ27220 获取电量数据后发送给 ESP32。

### 对齐结论

- BQ27220 是唯一可信电量来源。
- ESP32 不独立估算电量。
- GP41 ADC 只作为 fallback 或调试项，不作为正常 SOC/FCC 来源。

## 4. VBUS 与电池电压采样

### 已有硬件

- GP21 = VBUS-present sense
- GP41 = VBAT sense / ADC1

### 对齐结论

- GP21 用于判断 USB/VBUS 是否存在。
- GP41 可作为电池电压调试辅助。
- 正式 SOC/FCC 以 BQ27220 为准。
- VBUS 只能标记外部供电状态，不能直接把电量强制为 100%。
