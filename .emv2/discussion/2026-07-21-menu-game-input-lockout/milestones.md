# 子流程拆分: 菜单期间锁定游戏交互

讨论ID: `2026-07-21-menu-game-input-lockout`
步骤编号: `S24`

## S24-A: RP2350 菜单锁存与 GP19 保留

- 菜单打开同一轮进入锁定。
- 退出后等待 GP2～GP20 原始值和消抖值全部释放并稳定 30ms。
- GP19 保持菜单 `BACK/退出`，但其游戏 A2 由输出层屏蔽。

## S24-B: RP2350 USB 与本地输入保护

- USB 驱动在锁定期间接收 neutral 状态和屏蔽后的 GP2～GP20 GPIO。
- 暂停普通/重启热键、Turbo 修改与输出、输入宏。
- 保留真实 `processedGamepad`，避免破坏 ESP32 原始输入快照。

## S24-C: FP 锁标志与 ESP32 共享文档

- `FP` Byte4 bit7 发布 RP2350 游戏输入锁状态。
- 保持帧长、类型、周期、按钮和轴字段不变。
- 输出 ESP32-C6 AI 可直接执行的 BLE 锁定协议与测试清单。

## S24-D: RP2350 非编译静态验证

- 检查进入/退出同轮、GP19/GP20、USB临时状态恢复、FP校验和协议文档。
- 执行定向源码搜索和 `git diff --check`；不运行编译。

## S24-E: 跨 MCU 构建与实机验证

- ESP32 AI 按共享文档实现 C6 侧状态机。
- 用户分别构建、烧录 RP2350 与 ESP32-C6。
- 验证 USB、BLE、GP19 BACK、Turbo/宏、按住进入与退出释放。

## 用户确认

用户确认混合方案，并要求先修改 RP2350、再用共享文档指导 ESP32 侧 AI。
